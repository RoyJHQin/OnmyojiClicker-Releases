# 3.0 配置手册

这份手册不解释每一个参数，而是帮助你理解程序怎么判断、哪些内容必须自己配置，以及怎样确认它不会乱点。

具体示例数值单独保存在 [onmyoji-reference.json](../examples/onmyoji-reference.json)。它只用于对照，不代表适合你的电脑。

## 先理解三个区域

无论使用哪种模式，最容易混淆的是下面三个概念：

- **目标窗口**：程序只读取和操作你选中的《阴阳师》窗口。
- **检测区域**：程序在这里“看”，判断当前是什么页面或有没有目标。
- **点击区域**：程序在这里“点”。它可以和检测区域不同。

此外还有一层**游戏安全区域**。所有点击和拖动都必须留在这个边界内，用来避免操作到标题栏、Dock、桌面或其他应用。

窗口移动、缩放、切换显示器或修改游戏分辨率后，原来的区域都可能失效。即使 Mac 型号相同，也不能跳过核对。

## 模式一：区域随机点击

### 程序怎么运行

这个模式不看画面，也不知道当前处于哪个页面。启动后，它只会在指定区域内随机取点，按照设定节奏持续点击，直到达到停止条件或用户按下 `Esc`。

因此，它适合按钮固定、页面不会变化的场景；不适合附近存在购买、删除、消耗资源或其他危险按钮的界面。

### 你必须确认什么

1. 目标应用确实是《阴阳师》。
2. 安全区域只覆盖游戏内容。
3. 点击区域始终落在目标按钮内。
4. 游戏进入其他页面后，这个区域不会变成危险按钮。
5. 运行时长、点击节奏和自动休息符合你的计划。

这个模式的核心不是“参数调得多准”，而是确认在整个运行过程中，同一位置一直可以安全点击。

## 模式二：画面识别回合

### 程序怎么运行

这个模式处理的是固定循环：

```text
识别开始画面 → 点击开始 → 等待战斗 → 识别结算画面 → 点击结算 → 回到下一轮
```

程序只有在参考图与当前画面足够接近时才会点击。开始图和结算图分别拥有自己的检测区域与点击区域。

“检测区域”应该包含能够证明当前页面身份的稳定内容；“点击区域”只需要覆盖真正要点的按钮。检测成功不代表点击位置一定正确，两者必须分别测试。

### 一套方案代表什么

御魂、爬塔或活动副本的页面和节奏不同，应分别建立方案。切换方案时，参考图、位置、等待逻辑和停止条件会一起切换。

不要用“御魂”的参考图配“爬塔”的点击位置，也不要在更换窗口尺寸后继续沿用旧方案。

### 你必须确认什么

1. 开始页面能够稳定识别。
2. 战斗中、弹窗中或相似页面不会被误认成开始页面。
3. 结算页面能够稳定识别。
4. 相似的奖励页、活动页不会被误认成结算页面。
5. 点击开始后，程序不会盲等过久；战斗结束后能够及时进入结算判断。
6. 完整跑完一轮后，再增加运行时长或回合数。

## 模式三：动态探索副本

### 程序怎么运行

动态探索不是简单的固定回合，而是一套状态流程。程序会不断判断自己处于哪一种页面，再决定下一步：

```text
章节选择页
  ↓ 点击目标章节
探索入口
  ↓ 点击进入
探索地图
  ├─ 找到首领目标 → 点击战斗
  ├─ 找到普通目标 → 点击战斗
  └─ 没有目标 → 拖动地图后继续搜索
战斗页面
  ↓ 等待结束
结算或宝箱页面
  ↓ 点击继续
返回地图或开始下一轮
```

如果画面长期无法归类，正确行为应该是停止并等待检查，而不是持续盲点。

### 为什么需要多类参考图

每张参考图只回答一个问题，例如“现在是否在探索地图”或“战斗是否已经结束”。普通战斗目标和首领目标则用于决定地图上的点击位置。

这些内容缺少任何一项，都可能让流程停在中间：

- 缺少地图页识别，程序不知道何时开始找目标；
- 缺少战斗页识别，程序不知道战斗是否仍在进行；
- 缺少结算或宝箱识别，程序无法安全进入下一步；
- 地图搜索范围错误，程序可能把装饰图案当成目标，或完全看不到真实目标；
- 拖动区域错误，程序可能拖到界面按钮或安全区域之外。

### 你必须确认什么

1. 章节、入口、地图、战斗、宝箱和结算页面都能单独识别。
2. 普通目标与首领目标在实际地图中能被找到，不会命中固定装饰。
3. 地图搜索范围覆盖目标可能出现的位置，同时避开无关 UI。
4. 无目标时的拖动方向、起点和终点都安全。
5. 普通战斗、首领战斗、宝箱和返回地图的路径至少各完整验证一次。

## 哪些配置可以沿用，哪些必须重做

### 可以先沿用示例

- 点击与识别的等待节奏；
- 随机反应时间；
- 检测频率；
- 地图拖动的节奏；
- 识别阈值的初始参考。

这些值决定程序“多快行动”，可以先从示例开始，再根据实际战斗速度调整。

### 必须在本机重做

- 目标窗口与游戏安全区域；
- 所有检测位置和点击位置；
- 所有参考图；
- 地图搜索范围；
- 战斗目标大小与地图拖动位置。

这些内容依赖屏幕、窗口和游戏画面。直接复制别人的配置，最大的风险不是“识别失败”，而是识别后点到了错误位置。

## 参考图怎样才算合格

好的参考图应当稳定、清晰，并且只在目标页面出现。

- 保留能区分页面身份的文字、图标或固定结构；
- 避开大面积动画、粒子效果和不断变化的数字；
- 同一状态可以采集多个轻微不同的样本；
- 不要把其他页面的图片混进同一类别；
- 游戏更新、窗口尺寸或显示缩放变化后重新采集。

测试时不要只测正确页面。还要打开最相似的错误页面，确认它不会通过。这一步比单纯追求更高识别分数更重要。

## 怎样判断配置已经可以运行

只有满足下面条件，才建议从短时测试进入正常运行：

- 程序读取的是正确窗口；
- 所有点击和拖动都在安全区域内；
- 正确页面能识别，相似错误页面不能识别；
- 模式二能够完整跑完一个回合；
- 模式三能够走完实际会遇到的主要分支；
- 按下 `Esc` 后立即停止，不再继续点击；
- 遇到未知画面时会等待或停止，而不是盲目操作。

首次运行应选择最短的停止条件，并保持游戏窗口可见。确认一轮完整行为正确后，再逐步增加运行时间。

## 常见问题怎么看

| 现象 | 通常意味着什么 | 优先检查 |
|---|---|---|
| 一直等待，没有点击 | 当前页面没有通过识别 | 参考图、检测区域、窗口尺寸 |
| 识别成功但点错位置 | 点击区域与当前窗口不匹配 | 点击位置、安全区域、窗口是否移动 |
| 把相似页面当成目标 | 参考图区分度不足 | 缩小检测范围，加入更有辨识度的内容 |
| 探索地图一直找不到目标 | 搜索范围或目标特征不匹配 | 地图范围、目标大小、当前动画状态 |
| 地图反复拖动 | 程序确认在地图页，但没有发现目标 | 目标识别、拖动后等待、地图是否已清空 |
| 流程停在宝箱或结算 | 对应状态没有被识别 | 宝箱/结算参考图和检测区域 |

诊断日志用于回答“程序当时认为自己看到了什么、为什么没有进入下一步”。它适合排查问题，但不能替代实际画面测试。

## 示例配置的边界

示例文件保留了验证环境中的数值和流程结构，但有意移除了参考图、模板文件名、配置身份和运行日志。

它的用途是让你理解一套完整配置由哪些部分组成，而不是一键复制后直接运行。真正决定安全性的仍然是你在本机完成的画面、位置和完整流程测试。
